# 从 Flask 到 FastAPI：按你餐厅项目的顺序走一遍

方法只有一条：**同一个业务，用 FastAPI 重写一遍，每写完一块就问自己「换成 Flask 我会怎么写」。** 差异自己找出来的，才记得住。

---

## 一、阶段总览

| 阶段 | 做什么 | 对应你项目里的东西 | 状态 |
| --- | --- | --- | --- |
| 0 | 工程骨架 + 配置 + 健康检查 | `backend/app/__init__.py`、`config.py` | 已完成 |
| 1 | 数据库接入 + 第一个模型 | `extensions.py`、`models/base.py` | 已完成（迁移留作练习） |
| 2 | 第一个 CRUD 竖切 | `api/stores.py` + `services/store_service.py` | 参考实现已给，练习是你写 |
| 3 | 认证与权限 | `flask_login`、`utils/token.py`、`rbac.py`、`utils/decorators.py` | 待做 |
| 4 | 事务与并发 | `order_service.py`、`balance_service.py` | 待做 |
| 5 | 文件上传与静态托管 | 菜品图片、`_serve_spa` | 待做 |
| 6 | 缓存与后台任务 | `Flask-Caching`、Redis | 待做 |
| 7 | 流式与实时（毕设必需） | 餐厅项目没有，毕设的口语陪练要用 | 待做 |
| 8 | 测试与部署 | `backend/tests`、Dockerfile、nginx | 待做 |

前 6 个阶段是「把餐厅后端重写一遍」，后 2 个阶段开始转向你的毕设。

## 二、文件对照表

| Flask 项目 | 这个项目 | 变化点 |
| --- | --- | --- |
| `app/__init__.py` `create_app()` | `app/main.py` `create_app()` | 蓝图注册 → `include_router`；`before_first_request` → `lifespan` |
| `app/config.py` 配置类 | `app/core/config.py` `Settings` | 类继承 → 环境变量 + 类型校验 |
| `app/extensions.py` 扩展单例 | `app/db/session.py` + `app/api/deps.py` | 全局单例 + `init_app` → 普通对象 + `Depends` |
| `app/errors.py` `BusinessError` | `app/core/errors.py` `AppError` | 多一个机器可读的 `code` |
| `app/utils/api_response.py` | `app/core/response.py` `ApiResponse[T]` | 拼 dict → Pydantic 泛型 |
| `app/models/base.py` | `app/db/base.py` | `db.Model` → `DeclarativeBase` + `Mapped` |
| `app/schemas/*.py`（marshmallow） | `app/schemas/*.py`（Pydantic） | `@bp.arguments` 校验 → 类型即校验 |
| `app/services/*.py` | `app/services/*.py` | 思路不变，但要去掉 `current_user` 和 `db.session` 全局引用 |
| `app/api/*.py`（flask-smorest） | `app/api/v1/*.py`（APIRouter） | 装饰器顺序、依赖声明方式变了 |
| `utils/decorators.py` `@permission_required` | `Depends(require_permission(...))` | 装饰器 → 依赖 |
| `utils/token.py` | 阶段 3 自己写 | 逻辑可原样搬 |
| `Flask-Migrate` | `alembic` | 同一套底层，命令更直接 |
| `backend/tests/*.py` | `tests/*.py` | `app.test_client()` → `TestClient(app)` |

## 三、阶段 0：骨架（已完成）

跑起来，然后逐行读 `app/main.py`，确认你能回答这五个问题：

1. 为什么保留 `create_app()` 工厂，而不是模块级 `app = FastAPI()`？
2. `lifespan` 对应 Flask 的哪个钩子？为什么不用 `@app.on_event("startup")`？
3. 为什么 `/health` 用 `async def`，而 `/stores` 用普通 `def`？
4. `response_model=ApiResponse[StoreOut]` 具体做了什么？如果 service 多返回一个 `password_hash` 会怎样？
5. `/docs` 里的请求体长什么样，是从哪来的？

**验收**：不看代码，能对着空文件把 `main.py` 的结构说清楚。

## 四、阶段 1：数据库（已完成 80%）

已经有的：`engine`、`SessionLocal`、`get_db` 依赖、`BaseModel`、`Store` 模型。

**练习 1**：加 `Category` 模型（`name` / `sort_order` / `is_active`），重启服务，看 `data/dev.db` 里多出来的表。

**练习 2（重点，别跳）**：把 `create_all` 换成 Alembic。

先删掉 `data/dev.db`（这是学习用的临时库，里面只有一条演示数据，删了不影响任何东西），让 Alembic 从零建表，否则会撞上「表已存在」。

```bash
pip install alembic
alembic init migrations
```

然后改 `migrations/env.py` 两处：`target_metadata = Base.metadata`，并 `import app.models`。再执行：

```bash
alembic revision --autogenerate -m "init"
alembic upgrade head
```

最后删掉 `main.py` 里 `lifespan` 中的 `create_all`。

**验收**：改一次 `Store` 模型，`--autogenerate` 能生成正确的迁移；`upgrade head` 后再 `downgrade -1`，表结构回到上一版。做到这两步，你以后加字段就不会再手动改库了。

**坑**：`env.py` 不 import 模型，生成的迁移永远是空的。

## 五、阶段 2：第一个 CRUD（参考实现已给，练习是你写）

先读这一条竖切，顺序是 `schemas/store.py` → `repositories/store_repo.py` → `services/store_service.py` → `api/v1/stores.py`，边读边回答：

1. 谁负责 `commit`？为什么 repository 只 `flush` 不 `commit`？
2. 「同名门店」这个判断为什么在 service，而不在 router？
3. 404 是谁抛的？HTTP 状态码是谁决定的？

**练习**：自己写 `categories` 模块，四个接口：列表、新增、改名、停用。要求：

1. 路由函数里不出现 SQL、不出现业务 `if`
2. service 里不出现 `fastapi` 三个字
3. 至少 4 个 pytest 用例，覆盖成功、404、409、422

**写不出来时再看 store，写完把 store 关掉重写一遍。** 这一步决定你后面所有模块的速度。

**对照点**：`@bp.arguments(LoginSchema, location='json')` 和「把参数类型写成 `payload: StoreCreate`」，是同一件事的两种实现；前者是插件补的，后者是语言本身给的。

## 六、阶段 3：认证与权限

对应你项目里的 `flask_login` + `utils/token.py` + `utils/decorators.py` + `rbac.py`。

**要做**：

1. `core/security.py`：密码哈希、JWT 签发与解析（`pyjwt`）
2. `api/deps.py`：`get_current_user`、`require_permission(*codes)` 依赖工厂
3. `services/auth_service.py`：登录、登出（`token_version` 自增让旧 token 失效）
4. 数据范围过滤放在 service，用参数传 `current_user`

**验收**：未登录 401；权限不足 403；把账号 `is_active` 改成 False，手里的旧 token 下一个请求立刻失效。

**关键差异**：你的 `AuthService.logout()` 里写了 `current_user` —— 这在 Flask 里能跑，但它意味着 service 依赖了框架。FastAPI 版本里，把 `user` 作为参数传进去。这是本项目最重要的一个习惯。

---

## 七、阶段 4：事务与并发

对应 `order_service.py`、`balance_service.py`（你那份「行锁」的提交记录就是这一步的产物）。

**要做**：下单接口 + 状态机 + `SELECT ... FOR UPDATE` + 幂等键。

**验收**：20 个并发请求抢同一份库存，最终数量正确、没有超卖；中间失败能整体回滚。

**坑**：SQLite 的行锁不生效，这一步必须切到 PostgreSQL 验证，否则测了等于没测。

---

## 八、阶段 5：文件与静态资源

对应菜品图片，以及 `app/__init__.py` 里的 `_serve_spa`。

**要做**：`UploadFile` 上传（大小、类型校验）、静态目录挂载、SPA fallback，`/api/*` 未命中要返回 JSON 而不是 HTML。

**验收**：上传 → 访问 → 删除全通；随便打一个不存在的 `/api/xxx`，拿到的是 JSON 404。

---

## 九、阶段 6：缓存与后台任务

**要做**：热点接口加 Redis 缓存；耗时操作（比如生成报表）用 `BackgroundTasks`。

**验收**：第二次请求命中缓存（看日志里的 SQL 少了）；后台任务抛异常不影响主响应。

**坑**：`BackgroundTasks` 在同进程内，重启就丢。只用来做「丢了也无所谓」的事；要可靠就上 Celery/RQ。

---

## 十、阶段 7：流式与实时（毕设的核心）

餐厅项目里没有这一块，但你的毕设全靠它：大模型逐字输出、语音上传、实时对话。

**要做**：

1. `StreamingResponse` 做 SSE，把 LLM 的 token 一个个吐给客户端
2. `WebSocket` 接音频分片上传（先做「按住说话 → 整段上传」，不要一上来做全双工）
3. 用 `asyncio.gather` 并行跑 ASR 和检索

**验收**：`curl -N` 能看到逐字输出；两个客户端同时连接互不阻塞；一个慢请求不会拖死别人的 `/health`。

**坑（最重要）**：`async def` 里调同步 SDK，整个事件循环会被堵死，症状是「一个人说话，所有人都卡住」。要么用异步客户端，要么 `await run_in_threadpool(...)`。

---

## 十一、阶段 8：测试与部署

**要做**：pytest 覆盖核心用例、Docker 多阶段构建、`uvicorn --workers`、nginx 反代、`/health` 探活。

**验收**：`docker compose up` 一条命令起服务，重启后数据还在。

---

## 十二、每阶段的自检三问

1. 这一层能不能不启动 HTTP 服务、单独用 pytest 测？（测不了 = 耦合了）
2. 把数据库从 SQLite 换成 PostgreSQL，要改几个文件？（>2 个 = 写死了）
3. 给实体加一个字段，要改几处？（超过「模型 + schema + 迁移」三处 = 有重复定义）

---

## 十三、八个常见坑（提前知道能省好几天）

1. `async def` 里调同步库，堵死事件循环。
2. 依赖注入里拿到 session，service 里又 `commit` 一次，事务边界混乱。
3. `response_model` 遇到懒加载关系，报 `DetachedInstanceError` 或悄悄 N+1。
4. 把 Pydantic v1 的 `@validator` 写法抄进 v2 项目（v2 是 `@field_validator`）。
5. 参数校验失败返回 422，业务校验失败也返回 422，客户端分不清。
6. `/stores/{id}` 写在 `/stores/search` 前面，把静态路由吃了。
7. 生产环境还开着 `allow_origins=["*"]`。
8. `datetime.now()` 和 `utcnow()` 混用，时间差 8 小时。
